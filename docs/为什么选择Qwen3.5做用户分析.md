# 为什么选择 Qwen3.5 进行用户标签判定与画像生成

## 一、背景与挑战

社交媒体用户的风险识别是一项复杂的语义理解任务，面临以下核心挑战：

- **多语言混杂**：推文内容涵盖中文、英文、阿拉伯语等多种语言
- **语义隐晦**：风险内容往往通过隐语、暗语、转发等间接方式表达，关键词匹配无法覆盖
- **多维度判断**：需要综合账号资料、发帖内容、互动行为、关注关系等多个维度
- **标签互斥复杂**：多标签体系下需要处理"无敏感倾向"与其他标签的互斥逻辑
- **画像生成要求高**：用户画像需要客观、准确、信息密度高，不能凭空捏造

传统的关键词匹配和规则引擎只能覆盖已知的明确词汇，面对上述挑战力不从心。

---

## 二、为什么选择大语言模型

### 2.1 语义理解能力

大语言模型通过海量文本训练，具备深层语义理解能力，能够：

- 识别隐晦表达（如"某领导人"的负面暗语）
- 理解上下文语境（同一词汇在不同语境下含义不同）
- 跨语言理解（无需翻译即可分析英文、阿拉伯文推文）

### 2.2 多标签灵活输出

传统分类模型通常是单标签或固定类别，大模型可以：

- 同时输出多个标签（如"涉政 + 涉及仇恨言论"）
- 根据证据强度决定是否打标
- 严格遵守标签互斥规则（有敏感标签时不输出"无敏感倾向"）

### 2.3 综合推理能力

用户分析需要综合多个信息源，大模型可以在一次调用中：

- 分析账号基础资料（简介、定位、专业领域）
- 理解推文和回复内容的语义
- 结合关注关系（是否关注敏感账号）
- 输出有逻辑依据的判定结果

---

## 三、为什么选择 Qwen3.5

### 3.1 中文理解能力强

Qwen3.5 由阿里巴巴研发，在中文语料上进行了大规模训练，对中文语义、文化背景、政治敏感词汇的理解显著优于通用英文模型（如 GPT-3.5）。

### 3.2 支持长上下文

单个用户的分析输入包含：

- 账号基础资料
- 最多 20 条推文样本
- 最多 20 条回复样本
- 关注账号列表
- 规则预判结果

Qwen3.5 支持长上下文窗口，能够在一次请求中处理完整的用户信息，无需分批截断。

### 3.3 本地私有化部署

本项目使用 **Qwen3.5-27B 本地部署版本**，运行在内网服务器（双卡 RTX 4090）上，具备以下优势：

| 优势 | 说明 |
|------|------|
| 数据安全 | 用户数据不出内网，不经过任何第三方 API |
| 无调用费用 | 无 token 计费，可大批量处理 |
| 低延迟 | 内网直连，无公网传输延迟 |
| 可控性强 | 模型版本固定，结果稳定可复现 |

### 3.4 OpenAI 兼容接口

Qwen3.5 提供标准的 OpenAI 兼容 API，系统可以无缝切换到其他模型（如 GPT-4、Claude），无需修改业务代码。

## 四、技术实现细节

### 4.1 两阶段分析策略

为了提升准确率并降低模型幻觉，系统采用"规则预判 + LLM 归一判定"的两阶段策略：

```
第一阶段：规则预判
├── 检查是否关注涉政敏感账号名单（23个账号）
├── 关键词匹配（涉政、涉恐、涉赌等关键词库）
└── 输出候选标签（作为 LLM 的参考输入）

第二阶段：LLM 综合判定
├── 输入：用户资料 + 文本样本 + 候选标签
├── 模型：Qwen3.5-27B（本地部署）
└── 输出：最终标签 + 用户画像 + 判定依据
```

规则预判的作用是给模型提供"线索"，减少模型需要从零推理的工作量，同时降低漏判风险。

### 4.2 Prompt 设计

系统 Prompt 明确要求模型：

1. 只输出严格 JSON 格式，不输出思考过程
2. 标签只能从固定集合中选择
3. 有敏感标签时不得包含"无敏感倾向"
4. 用户画像必须基于真实字段，不得虚构
5. 画像风格客观、简洁，使用"当前可见数据表明"等规范表达

```
输出格式示例：
{
  "labels": ["涉政", "涉及仇恨言论"],
  "reasoning_brief": "用户多次转发针对国家领导人的负面内容，并关注多个涉政敏感账号",
  "profile_summary": "该用户为中高活跃账号，关注者规模较大，内容呈现明显涉政倾向..."
}
```

### 4.3 标签归一化

模型输出后，系统进行严格的标签归一化处理：

- 过滤非法标签（不在允许集合内的标签一律丢弃）
- 合并规则标签与模型标签（取并集）
- 处理互斥规则（有敏感标签则移除"无敏感倾向"）
- 按固定顺序输出（涉政 → 涉恐怖极端 → 涉及传播淫秽赌博 → 涉及网络犯罪或者网络暴力 → 涉及仇恨言论 → 无敏感倾向）

### 4.4 文本预处理

送入模型前，系统对文本进行以下处理：

1. **清洗**：去除前后空白、超长重复字符
2. **URL 展开**：自动展开 t.co 短链，抓取目标页面 title/description，补充到原文中
3. **去重**：同一用户的重复文本去重后再送模型
4. **截断**：单条文本超过 1000 字符时截断，防止超出上下文限制

### 4.5 容错与重试

- 模型 JSON 输出异常时，使用括号配对算法提取 JSON 块，容错处理
- 单个用户分析失败不影响整体批次，记录日志后跳过
- 模型接口超时自动重试（最多 3 次）

## 六、总结

选择 Qwen3.5 本地部署方案，是在**数据安全、分析准确率、成本控制**三者之间取得最优平衡的结果。相比纯规则引擎，大模型能够理解语义隐晦的风险内容；相比调用公有云 API，本地部署保障了数据主权，且无调用成本限制，适合大批量持续分析的业务场景。
